# YEE-75 deterministic text normalization

Version: `yee-75-text-normalization-v0.1`.

Input text is limited to accepted YEE-73 confirmed-member `title` and `summary`. Source fields remain unchanged in the input and representative evidence. Matching uses Unicode NFKC, lowercase tokens, conservative camel-case boundaries, and punctuation/whitespace/underscore/hyphen token boundaries. Standalone dotted Minecraft versions and dotted version ranges are blanked before token generation; numeric-only tokens do not become phrase content. This includes forms such as `1.20.4`, `1.20-1.21`, and `1.21+`.

The first non-empty summary sentence is selected by punctuation or line boundary, then normalized. Its candidate surface is capped at 240 normalized characters, retaining only complete tokens within the cap. Title n-grams are sizes 1–3; summary-first-sentence n-grams are sizes 2–3. A phrase consisting only of stoplist/generic/numeric/version tokens is rejected. Mixed phrases retain their original contiguous tokens, then pass the separate versioned functional-direction guard (`yee-75-functional-direction-guard-v0.1`) before support/broadness admission. That deterministic guard rejects recurring prose/marketing scaffolding when it has no functional content token, as well as article/boilerplate-led or dangling-connector fragments. It does not rewrite or stem an admitted phrase. Examples rejected include `a fully`, `better`, `players with`, `to create`, `plugin designed to`, and `plugin that enables`; functional controls such as `death message`, `custom recipes`, `item frames`, and `skip the night` remain eligible.

Versioned stoplist: `a, an, and, are, as, at, be, been, being, but, by, can, could, do, does, for, from, had, has, have, he, her, here, hers, herself, him, himself, his, how, i, if, in, into, is, it, its, itself, just, me, more, most, my, myself, new, no, nor, not, of, off, on, once, only, or, other, our, ours, ourselves, out, over, own, same, she, should, so, some, such, than, that, the, their, theirs, them, themselves, then, there, these, they, this, those, through, to, too, under, until, up, very, was, we, were, what, when, where, which, while, who, whom, why, will, with, would, you, your, yours, yourself, yourselves, allow, allows, allowed, add, adds, added, also, make, makes, made, use, uses, used, using, work, works, working, get, gets, getting, give, gives, giving, include, includes, including, support, supports, supported, compatible, compatibility, version, versions, resource, resources, plugin, plugins, minecraft, paper, spigot, bukkit, purpur, folia, velocity, waterfall, server, servers, proxy, premium, free, paid, addon, add-on, download, downloads, updated, update, updates`.

Taxonomy-label guard removes phrases exactly equal to the normalized category name or frozen subcategory ID (underscores represented as spaces). The functional-direction guard is a separate semantic admission gate over exact lexical tokens; it does not change whitespace arithmetic, source-local metrics, category membership, or coverage-risk logic. No stopword expansion, stemming, fuzzy match, embeddings, semantic merge, or model inference is used.

For lexical membership, the exact normalized phrase occurrence is recorded. When repeated, choose title before summary, then earliest span. The span substring and offsets are emitted only if NFKC leaves the relevant source surface byte-index-compatible; otherwise the normalized match remains and the original span is null.
